# Focused privilege-elevation review

## Conclusion

**No built-in exploit or demonstrated mechanism to elevate a standard user's command execution to Administrator/SYSTEM was identified in the supplied MSI and extracted executable.** This is a bounded static finding, not a proof that every possible elevation technique is absent. Follow-on commands and payloads from the controller were not available.

The observed remote execution handler normally creates child processes under the agent's existing security context. If the agent already runs elevated, its commands may inherit elevated access; that would not itself demonstrate an exploit in this file. The victim process token and installation context require endpoint telemetry to establish.

## Direct evidence

1. **Process creation:** `main.premiere` (VA 0x1402747a0) uses `os/exec.Command` + `Cmd.Start` for asynchronous execution, or `CommandContext` + `CombinedOutput` for ordinary execution. Both allocate a zero-initialized Windows `SysProcAttr` and set only its first byte to 1 (0x14027489e and 0x1402749a9). Embedded Go reflection confirms that byte is `HideWindow`; `Token` at offset 0x20, `CreationFlags` at 0x18 and `ParentProcess` at 0x58 remain zero in those objects. Hidden windows do not elevate privileges. See [disassembly](disassembly/main.premiere.asm) and [decoded field offsets](sysprocattr-layout.json).
2. **Potentially misleading library APIs:** `CreateProcessAsUser` appears in the compiled Go `syscall.StartProcess` library implementation alongside ordinary `CreateProcess`. Its presence does not demonstrate token theft or elevation; the reviewed application handler does not supply an alternate token. Strings including `AdjustTokenPrivileges`, `DuplicateTokenEx`, `ImpersonateLoggedOnUser` and `OpenProcessToken` also occur in bundled Windows API name data. No application-level elevation chain using them was established. See [library disassembly](disassembly/syscall.StartProcess.asm).
3. **MSI execution:** the sole custom action is Type 210, an immediate installed-EXE launch with asynchronous/ignore-return flags. It is not a deferred non-impersonating custom action. The exported MSI tables do not set `AlwaysInstallElevated` or declare a separate elevated helper, service, driver, script or elevation custom action. The payload destination and Run persistence are user-scoped. See [custom action](tables/CustomAction.idt), [properties](tables/Property.idt), [registry](tables/Registry.idt), and [installer detail](installer-findings.md). These facts do not establish the actual Windows Installer process identity or exclude a preexisting host policy/misconfiguration.
4. **Resources and attached payloads:** a parsed PE resource inventory contains icon resources (types 3 and 14) and version information (type 16); no embedded executable manifest (type 24) or separately identified exploit/helper resource was present. There are no bytes after the last PE section. This does not rule out encoded data within sections, but no such elevation payload was established during the review.
5. **Bounded searches:** searched recovered strings, 6,584 Go function names, MSI tables and reviewed application disassembly for UAC/elevation declarations, runas/ShellExecute, token/impersonation APIs, driver interaction, common UAC-bypass target names and CVE identifiers. No demonstrated elevation exploit resulted. The application's `noise` functions contain computation with no direct external calls except initialization time/runtime helpers; they did not establish elevation behavior. String absence or presence alone was not treated as proof.

## Remaining incident questions

The remote `exec` command accepts arbitrary program names and arguments. The attacker could therefore supply a separate privilege-escalation tool, use credentials obtained elsewhere, or ask the user to approve elevation. None of those events can be inferred from this sample alone. Check EDR process integrity level/token elevation, parent-child process history, installer logs, privilege-related events and additional dropped binaries to determine whether elevation occurred on the colleague's endpoint.
